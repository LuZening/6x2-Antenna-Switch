## Development Rules

### CubeMX Code Preservation

This project uses STM32CubeIDE. **All code outside `/* USER CODE BEGIN ... */` and `/* USER CODE END ... */` sections is auto-generated by CubeMX and will be overwritten on regeneration.**

- Only modify code within USER CODE sections
- When adding new functionality, place it inside appropriate USER CODE blocks
- Do not modify auto-generated initialization functions (SystemClock_Config, MX_GPIO_Init, etc.)

### Documentation Requirements

All modifications must be documented in three categories:

1. **Network Protocol Documentation** - `doc/network/` directory
   - HTTP server changes
   - WebSocket implementation
   - TCP/UDP protocol changes
   - Socket handling modifications

2. **Control Logic Documentation** - `doc/control/` directory
   - Antenna switching logic
   - RS485 communication
   - Configuration management
   - Command parsing

3. **Other Changes** - `doc/other/` directory
   - General improvements
   - Bug fixes not in above categories

Use **relative paths** or forward slashes `/` for paths (not Windows backslashes).

## Project Overview

This is an **STM32F030C8TX** firmware for a **6x2 Antenna Switch** controller. It controls 2 antenna selectors (each switching between 6 antennas) via BCD output pins and exposes control via Ethernet (HTTP/WebSocket/TCP/UDP) and RS485 serial.

## Building

**IDE**: STM32CubeIDE (project uses `.cproject` format)
- Open `MCU2/Antenna Switch 6x2 New.ioc` in STM32CubeIDE
- Build from IDE: Project → Build All
- Output binaries in `MCU2/Debug/` and `MCU2/Release/`

**Web UI Update** (when modifying webpage):
- After editing `data_uncomp/index.html`, run:
  ```
  cd tools && ./generate_data_bin.bat
  ```
- This generates `data.bin` which needs to be flashed to the device's filesystem area (FS_BASE_ADDR = 0x0800C000)

## Architecture

The firmware runs a super-loop with these main tasks:
1. **CH395 Ethernet handling** (`main.c:interrupt_CH395()`) - processes HTTP/WebSocket/TCP/UDP packets via CH395 chip on SPI1
2. **RS485 serial handling** (`main.c:Task0.5`) - parses commands from serial, executes them, sends responses
3. **Config persistence** (`main.c:Task1`) - auto-saves config to Flash every 3 seconds when modified
4. **IP display** (`main.c:Task2`) - monitors BCDM pins for IP display request from external CPLD

### Components

| Component | Location | Purpose |
|-----------|----------|---------|
| CH395 Ethernet | `Src/CH395*.c`, `Inc/CH395*.h` | SPI communication with CH395 Ethernet chip |

### Key Data Structures

- `Config` - stored in internal Flash (antenna mappings, network ports, antenna names)
- `AntennaSelector_typedef` - BCD pin definitions for each radio (2 selectors × 3 pins each)
- `CH395_TypeDef` - Ethernet chip state (8 sockets, buffers, connection status)
- `HTTPRequestParseState` - per-socket HTTP/WS connection state

### Antenna Switching

- Uses BCD output pins (active-low) to drive external relays
- `switch_Antenna(antnums, n)` in `main.c` - main switching function
- Prevents conflicts (same antenna assigned to multiple radios)
- `get_Antenna_real_BCDs()` reads back actual switch positions

### Network Protocols

- **HTTP** (port configurable, default 80) - serves embedded web UI, handles REST API
- **WebSocket** - upgraded from HTTP for real-time updates
- **TCP** (port configurable) - raw command interface (UART-over-IP)
- **UDP** (port configurable) - device discovery protocol

### Command Protocol

Commands come via RS485 or TCP and use simple `URI&arg=value` format:
- `URI=/switch&sel1=4&sel2=2` - switch antennas
- `URI=/getalloc` - get current allocation
- Responses broadcast to all WebSocket/TCP clients every 5 seconds

## Important Globals

- `cfg` - current configuration
- `Selector[2]` - antenna selector states (write outputs)
- `SelectorM[2]` - antenna selector monitors (read inputs)
- `ch395` - CH395 Ethernet chip state
- `parseStates[]` - per-socket HTTP parse states (6 sockets indexable by socket-1)
